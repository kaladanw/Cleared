# iOS distribution readiness

This is the release runbook for the Cleared host app and its Share Extension.
The current build is suitable for Simulator development only until every
blocking item below is complete. In particular, do not distribute a build that
contains the shared backend token.

## Hard gates before external TestFlight

- [ ] Replace `CLEARED_SHARED_TOKEN` with user/device authentication and
  server-side authorization plus per-user/device rate and spend limits. An
  xcconfig prevents a secret entering git; it does **not** prevent extraction
  from an installed app or extension. This requires a separate backend design
  decision and is intentionally not implemented here.
- [ ] Run the Photos -> Share -> Cleared flow on a physical iPhone using the
  production-signed host and extension. Confirm upload, report rendering,
  persistence into the shared app-group container, copy-question, Done, and a
  useful offline/server-error state.
- [ ] Confirm the public privacy policy and support URLs are live over HTTPS.

## Apple account, identifiers, signing, and capabilities

Use an Apple Developer Program team with automatic signing initially. In
Certificates, Identifiers & Profiles / Xcode, register and verify:

- host App ID: `com.kaladanw.cleared`
- extension App ID: `com.kaladanw.cleared.share` (a child of the host ID)
- App Group: `group.com.kaladanw.cleared`, enabled for both App IDs
- an App Store distribution profile/certificate for both targets (or Xcode
  managed equivalents)

Set `DEVELOPMENT_TEAM` locally or in CI; do not commit a personal team ID. Make
an Archive with the `Cleared` scheme and inspect the signing summary. The
archive must embed `ClearedShare.appex`, with the same Team ID, App Group, short
version, and build number as the host. No Associated Domains, Push, Sign in
with Apple, microphone, or speech capability is currently justified. Add them
only with the feature that needs them; voice/S6 is out of this release scope.

## Version and build numbers

`project.yml` owns the defaults for both targets:

- `MARKETING_VERSION` -> `CFBundleShortVersionString` (customer version)
- `CURRENT_PROJECT_VERSION` -> `CFBundleVersion` (uploaded build)

Increment the integer build for every App Store Connect upload. Change the
marketing version only for a new App Store version. Regenerate after changing
the manifest, then verify both built plists:

```sh
cd ios
/opt/homebrew/bin/xcodegen generate
xcodebuild -project Cleared.xcodeproj -scheme Cleared \
  -configuration Release -destination 'generic/platform=iOS' \
  -showBuildSettings | grep -E 'MARKETING_VERSION|CURRENT_PROJECT_VERSION'
```

CI may override the defaults without editing tracked files:

```sh
xcodebuild archive -project Cleared.xcodeproj -scheme Cleared \
  -destination 'generic/platform=iOS' -archivePath build/Cleared.xcarchive \
  MARKETING_VERSION=1.0 CURRENT_PROJECT_VERSION="$CI_BUILD_NUMBER"
```

Never reuse a build number for the same marketing version.

## Artwork and launch assets

Before archiving for upload, add `Cleared/Assets.xcassets` and configure
`ASSETCATALOG_COMPILER_APPICON_NAME: AppIcon` in `project.yml`. Supply an opaque
1024 x 1024 App Store icon (no alpha) and review all appearances generated by
Xcode, including dark/tinted variants if provided. Check it at small Settings
and share-sheet sizes; the extension uses the containing app's icon and does
not need a separate App Store icon.

The current `UILaunchScreen: {}` uses Apple's generated launch screen, which is
valid and preferable to a splash screen. Verify its background against light
and dark appearance on a device. App Store Connect also needs device screenshots
for each required display class; capture real final UI with no personal data,
debug overlays, or misleading report claims.

## Privacy, support, and marketing metadata

Publish stable HTTPS pages before submission:

- Privacy Policy URL (required): explain that listing screenshots and optional
  typed context are uploaded to Cleared's server and processed by an AI service;
  document retention/deletion, logs, subprocessors, security, contact method,
  and user rights. Keep it consistent with actual server behavior.
- Support URL (required): contact path, troubleshooting, service status or
  expected response time, and how to request data deletion.
- Marketing URL (optional): product explanation and download/TestFlight CTA.

Complete App Privacy in App Store Connect from verified data flows, not guesses.
Review at least User Content (photos and optional free-form text), identifiers,
diagnostics, product interaction, and whether any data is linked to identity or
used for tracking. Cleared should answer "no" to tracking only if neither it nor
its SDKs use data for cross-company tracking. There are currently no ad SDKs.

Before submission, inspect Apple's current required-reason API report from the
archive. Add `PrivacyInfo.xcprivacy` only when its declarations accurately match
the shipped APIs and data practices; an empty or speculative manifest is not a
privacy policy and can create a false declaration.

## App Store Connect and TestFlight checklist

- [ ] Create the app record with bundle ID `com.kaladanw.cleared`, SKU, primary
  language, category, age rating, and rights/content declarations.
- [ ] Add name, subtitle, description, keywords, copyright, privacy URL,
  support URL, and optional marketing URL. Avoid claiming authentication
  verdicts; describe Cleared as judgment-assist.
- [ ] Upload a Release archive and resolve every validation warning. Confirm
  icon, extension embedding, entitlements, versions, export compliance, and
  privacy manifest/API notices in Organizer/App Store Connect.
- [ ] Complete App Privacy and encryption/export-compliance questions. The app
  uses HTTPS; record Apple's exemption determination in release notes.
- [ ] Add required screenshots and an App Review note explaining: take listing
  screenshots, open Photos, select up to four images, Share, choose Cleared,
  optionally type context, then Check. Provide a working review account or
  other access mechanism after authentication replaces the shared token.
- [ ] Upload to internal TestFlight first. Test install/upgrade, extension
  discovery, share from Photos, slow request behavior, cancellation, backend
  failure, and last-report persistence on supported iOS 17+ devices.
- [ ] Add beta description, feedback email, privacy contact, and What to Test.
  Complete Beta App Review details before external testing.
- [ ] Record the tested build/version, devices, OS versions, tester, and result.
  Keep this branch unmerged until the physical-device smoke test passes.

## Release verification commands

These checks do not replace device and archive validation:

```sh
cd ios
/opt/homebrew/bin/xcodegen generate
xcodebuild -project Cleared.xcodeproj -scheme Cleared \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' test
git grep -n 'cleared-backend-production\|CLEARED_SHARED_TOKEN = [^p]' -- . \
  ':!ios/RELEASE.md'
```

The secret scan should not reveal a production host or real token in tracked
iOS files. `Secrets.xcconfig` must remain ignored and must never be attached to
release notes, CI logs, or source archives.
